# Aitext v0.1.0 Formal Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to execute this plan task-by-task with checkpoints. External GitHub mutations happen only in the final publish task after all local and CI evidence is green.

**Goal:** Rename the public project to Aitext, publish a clean unsigned Windows installer and portable ZIP as v0.1.0, and replace the single-language README with English/简体中文 Quick Start documentation and paired Paper Cut showcase assets.

**Architecture:** Keep the Rust application source and current working-tree feature work as the release source of truth. Build Windows artifacts reproducibly in GitHub Actions on `windows-latest` using Inno Setup, upload a per-user installer, portable ZIP, and SHA256SUMS, then publish the tag-triggered Release. Replace the old repository `main` and old v0.x Releases/tags only after the RC workflow has produced verified artifacts.

**Tech Stack:** Rust/Cargo, eframe/egui, Inno Setup, GitHub Actions, GitHub CLI, ffmpeg, built-in image generation, Markdown, PowerShell.

**Spec:** User-approved Aitext v0.1.0 release design from the 2026-08-20 conversation; repository target `naipi11/helix_copilot`, final name `Aitext`.

## Global Constraints

- Use v0.1.0 as the first Aitext release.
- Delete old Helix Copilot Releases and tags v0.1.0 through v0.2.6; do not create a legacy branch.
- Use an unsigned installer; do not invent or request a signing certificate.
- Do not launch or automate the desktop application; the user performs manual Windows testing.
- Do not send real API keys or vendor requests.
- Preserve LF line endings in README files and keep English/Chinese sections paired.
- Do not use `git reset --hard`, `git checkout --`, `git add -A`, or `git add .`.
- Stage only the explicitly listed release files and the current Aitext project source.
- Do not claim the Release exists until `gh release view` and downloaded asset hashes verify it.
